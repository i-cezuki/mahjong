# フェーズ7：卓のUIと牌の絵柄 設計

2026-10-02。`docs/SPEC.md` の Development Plan 7 にあたる。
SPEC の UI 節で確定している内容を前提にし、ここではフェーズ7で新しく決めたことと作り方を書く。

## 目的

通信確認用の仮の対局画面（牌は文字）を、牌の画像を使った卓の画面に作り直す。
サーバーとエンジンは変えない。画面データ `PlayerView`（`src/server/table.ts`）には合法手の一覧まで入っているので、画面側だけの作業になる。

## やらないこと

- 持ち時間の表示と時間切れ（フェーズ8）
- 効果音、牌が動くアニメーション、「ポン」「ロン」の発声演出
- ホームやルーム待機など、対局以外の画面の作り直し
- サイコロを和了者が1回ずつ操作して振る方式（サーバーの作り変えが必要なため採らない）

## 1. 牌の画像

### 素材

麻雀王国の麻雀素材（<https://mj-king.net/sozai/>）の「牌画2」を使う。縦向きのGIF、47×63px。
利用条件は「自由に使ってよい、連絡不要、改造と再配布も可、著作権は放棄しない、リンクか出典表示は歓迎」。

- 通常の牌は画像をそのまま `public/tiles/` に置く。ファイル名は牌の種類に合わせる（例：`5p.gif`、`1z.gif`）。
- 横向き（リーチ宣言牌、鳴いた牌）は、同じ画像をCSSで回転させる。横向きの画像は使わない。
- 高精細な画面では拡大されて少しぼやける。これは受け入れる。

### 素材に無い牌

素材の画像を加工して一度だけ生成し、生成物をコミットする。生成に使ったスクリプトも `scripts/` に残す。

| 牌           | 作り方                                                           | ファイル             |
| ------------ | ---------------------------------------------------------------- | -------------------- |
| 赤5筒、赤5索 | 5の絵柄を全部赤にする（素材の5筒は中央だけ赤なので全部赤で区別） | `5p-red`、`5s-red`   |
| 金5筒、金5索 | 5の絵柄を全部金色にする                                          | `5p-gold`、`5s-gold` |
| ポッチ       | 白牌の中央に赤い丸                                               | `5z-pocchi`          |
| 逆ポッチ     | 白牌の中央に青い丸                                               | `5z-reverse-pocchi`  |
| 花牌         | 白牌に「花」の字。4枚とも同じ絵柄（ルール上区別がない）          | `1f`                 |
| 裏向き       | 画像なし。青い無地の板をCSSで描く                                | —                    |

### 出典と仕様書

- ホーム画面の下に「牌画像：麻雀王国」のリンクを置く。
- `docs/SPEC.md` の UI 節「牌の絵柄は自作する…」を、「麻雀王国の牌画2を使い、無い牌だけ加工して作る」に書き換える。

## 2. 卓の配置

SPEC の確定内容どおり。固定レイアウトを1つ作り、端末の画面に収まるように全体を拡大縮小する。スマホでもPCでも同じ配置になる。大きさは 1040×480（実装時に 16:9 から変更した。スマホの横画面は 16:9 より横長なので、16:9 だと左右が余って牌が小さくなるため）。

```text
┌──────────────────────────────────────────────┐
│ 上家の名前      残り49枚             下家の名前 │
│ ┌─┐        ┌──────┬──────┬──────┐        ┌─┐ │
│ │裏│  副露  │      │東1局 │      │  副露  │裏│ │
│ │向│  花    │上家の│0本場 │下家の│  花    │向│ │
│ │き│        │ 河   │供託  │ 河   │        │き│ │
│ │手│        │      │ドラ  │      │        │手│ │
│ │牌│        │      │3人の点│     │        │牌│ │
│ └─┘        └──────┼──────┼──────┘        └─┘ │
│                   │自分の河│   [ポン][ロン][スキップ] │
│ [自動和了][鳴きなし]└──────┘         自分の副露・花 │
│   自分の手牌 ▯▯▯▯▯▯▯▯▯▯▯▯▯  ▯(ツモ牌)        │
└──────────────────────────────────────────────┘
```

- **中央パネル**：局、本場、供託、ドラ表示牌、3人の持ち点と風。手番の人の点数を明るくする。リーチ中の人にはリーチ棒を出す（2倍リーチは色違い）。
- **河**：6枚で折り返す。リーチ宣言牌は横向き、鳴かれた牌は薄くする。
- **相手の席**：裏向きの手牌（枚数分）、副露、抜いた花牌、名前。局が終わって公開された手牌は、席ではなく局の結果の中に出す。
- **自分の席**：手牌（`displayHand` でツモ牌を右端に離す）、副露、抜いた花牌。
- **席の並び**：自分が下、下家（次の手番の人）が右、上家が左。
- **縦画面**：「横にしてください」とだけ表示する。

## 3. 操作

- **打牌**：1回目のタップで牌が浮き、同じ牌をもう一度タップで打牌する。別の牌をタップすると浮く牌が切り替わる。画面データが更新されたら浮いた状態を解除する。
- **ボタン**：ポン、槓、ロン、ツモ、リーチ、スキップは、できるときだけ手牌の上に出す。
- **リーチ**：「リーチ」か「2倍リーチ」を押すと、切れる牌だけが明るくなり、選んだ牌で宣言する。取り消せる。
- **選択肢が複数あるポンと槓**（赤を含むか、どの牌を槓するか）：対象の牌を並べたボタンで選ぶ。
- **自動和了**：オンの間、ツモまたはロンが可能になったら自動で送る。
- **鳴きなし**：オンの間、ポンと大明槓しかできない応答は自動でスキップする。ロンができるときは止まる。
- 自動和了と鳴きなしはブラウザ側だけの機能で、サーバーは変えない。設定は対局をまたいで覚えない。同じ版番号に対しては1回しか自動で送らない。

## 4. 結果の画面

卓の上に重ねて表示する。

### 局の結果

- 和了：和了者ごとに、手牌、和了牌、役の一覧、翻数（役満は倍数）、裏ドラ表示牌、点棒と祝儀の移動。
- 流局：テンパイ者と公開された手牌、点棒の移動。
- 「確認」ボタンと、確認済みの人の表示。

### サイコロチャンス

- 指定する人には、ゾロ目以外の15通りの出目ボタンを出す。ほかの人には「◯◯が選んでいます」と出す。
- 出目が指定されると、3人の画面で1回ずつ順番に再生する。結果は今までどおりサーバーがまとめて決め、画面が順に見せる。
- 1回分の流れ：2個のサイコロが転がる（約1.2秒）→ 止まって出目が出る → 「当たり +70枚」「外れ」「ゾロ目 もう1回」を出す（約1秒）→ 次の回へ。
- 再生中は、指定した出目、何回目か（4回のうち）、ここまでの当たり枚数を出し続ける。2倍リーチ中は当たりが140枚。
- チャンスが複数あるときは、1つ再生し終えてから次の出目指定に進む。
- 「確認」ボタンと祝儀の合計は、再生が終わってから出す。
- 画面を読み込んだ時点ですでに届いていた結果は、再生せずに結果だけ表示する。

### 終局

順位、最終持ち点、スコア、祝儀、「ルームへ戻る」。

## 5. 部品の分け方

`src/app/games/[id]/game-client.tsx`（411行）を役割ごとに分ける。

| 場所                                       | 役割                                                                                                       |
| ------------------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| `src/components/tile.tsx`、`tile-image.ts` | 牌1枚の表示（表、裏、横向き、薄く）。牌IDから画像ファイルを決める                                          |
| `games/[id]/use-game-view.ts`              | 画面データを最新に保つ処理。今あるものを移すだけ                                                           |
| `games/[id]/game-client.tsx`               | 操作の送信と、部品の組み立て                                                                               |
| `games/[id]/table/`                        | 拡大縮小の枠と縦画面の案内、中央パネル、河、相手の席、自分の手牌、ボタン、局の結果、サイコロ、終局の各部品 |
| `games/[id]/logic/`                        | 画面に依存しない判断（下の3つ）                                                                            |

画面に依存しない判断は純粋な関数にして、単体テストを書く。

- **席の並び**：自分の席から、下家と上家の席を決める。
- **操作の整理**：`view.actions` をボタンにまとめる。リーチで切れる牌の一覧、選択肢が複数あるポンと槓、自動和了と鳴きなしで自動で送る操作。
- **サイコロの再生手順**：`DiceResult.rolls` を「何回目、当たり・外れ・ゾロ目、ここまでの枚数」の手順に変える。

## 6. エラーと取りこぼし

- 送信の失敗と版番号のずれは、今の仕組み（取り直して続ける、メッセージを出す）をそのまま使う。
- 通知の取りこぼしへの備え（4秒ごとの版番号の確認）もそのまま使う。

## 7. 確認の方法

- 単体テスト：席の並び、操作の整理、サイコロの再生手順。112枚すべての牌IDに画像ファイルが存在すること。
- 画面の確認：ローカルで自分とボット2人の対局を動かし、スマホ横画面（844×390）とPCの大きさでスクリーンショットを撮り、配置の崩れと牌の読みやすさを見る。局の結果、サイコロ、終局の画面も確認する。
- `typecheck`、`lint`、`test`、`build` が通ること。
- 最後に本番で利用者に触ってもらい、見た目の感想をもらう。
