# フェーズ8：持ち時間、切断、再接続 設計

2026-10-02。`docs/SPEC.md` の Development Plan 8 にあたる。
SPEC の「持ち時間（確定）」「持ち時間の実現（提案）」を前提にし、ここではフェーズ8で新しく決めたことと作り方を書く。

## 目的

- 手番、応答、サイコロの指定、局の結果に期限を付け、過ぎたら自動で進める。
- いなくなった人がいても、残った人が待たされずに半荘を終えられるようにする。
- 3人ともいなくなった対局を破棄し、参加者が新しいルームを作れるようにする。
- 1日1回の定期実行で、放置対局の破棄とSupabaseの一時停止防止を行う。

再接続（画面データの取り直し、4秒ごとの版番号確認）はフェーズ6で実装済みで、変えない。

## やらないこと

- 切断の検知（生存確認の送信、Realtime の Presence）。切断は時間切れだけで判定する。
- 他家の残り秒数の表示。
- 対局中の退出ボタン、対局の打ち切り（SPEC で「含めない」と確定済み）。
- エンジン（`src/engine/`）の変更。エンジンは時刻を知らないままにする。

## 1. 挙動

### 時間切れまでの流れ

1. サーバーは状態を保存するたびに次の期限の時刻を記録し、画面データに入れて3人に送る。
2. 期限を過ぎたら、画面を開いている誰かのブラウザが `POST /api/games/:id/tick` を送る。
3. サーバーは自分の時計で期限を確かめてから自動処理する。同時に届いた申告は、版番号の一致の検査で1つだけ通る。
4. 期限を過ぎていても、申告が処理される前に届いた本人の操作は受け付ける。

### 期限

| 場面               | 期限                                        |
| ------------------ | ------------------------------------------- |
| 手番               | 5秒＋その人の残り持ち時間                   |
| 他家の打牌への応答 | 15秒（応答できる人が2人でも期限は1つ）      |
| サイコロの指定     | 20秒＋直前のサイコロの演出の長さ            |
| 局の結果           | 15秒＋直前のサイコロの演出の長さ            |
| 対局の最初の手番   | 上の手番の期限に、画面の移動の分として+10秒 |

- 持ち時間は1人20秒。手番で5秒を超えた分だけ減る。局が変わると3人とも20秒に戻る。
- 1つの手番の中で槓をしたら、補充牌を引いたあとの待ちは改めて「5秒＋残り持ち時間」になる。
- サイコロの演出の長さは、その操作で振った回数（ゾロ目の振り直しを含む）×2.2秒。画面の再生時間（転がる1.2秒＋見せる1.0秒）と同じ定数を使う。

### 時間切れの自動処理

| 待っていた操作 | 自動処理                                                           |
| -------------- | ------------------------------------------------------------------ |
| 手番           | ツモ切り。ツモ牌がない（ポン直後）か切れないときは、切れる牌の右端 |
| 応答           | まだ応答していない人を全員スルーにする                             |
| サイコロの指定 | サーバーが乱数で出目を選んで振る                                   |
| 局の結果       | まだ確認していない人を全員確認済みにして次の局へ進む               |

和了できる形でも自動では和了しない（SPEC どおり）。

### 即ツモ切り（自動）の状態

- 手番、応答、サイコロの指定で時間切れした人は「自動」になる。局の結果の時間切れではならない。
- 自動の人の番は待たずに処理する。手番は即ツモ切り、応答は即スルー、サイコロは即指定、局の結果は確認済み扱い。
- 自動の人の処理は、きっかけになった操作や申告と同じ1回の保存の中で続けて行う。
- 3人とも自動になったら進行を止める（期限なし）。誰かが復帰すると再開する。
- 解除は本人の `resume` 操作で行う。画面に「自動ツモ切り中　タップで復帰」を出し、タップで送る。自動の人が送ったほかの操作でも解除する。
- 時間切れした人はその局の持ち時間を使い切っているので、復帰しても次の局までは毎手番5秒になる。

### 表示

- 自分が待たれているとき、手牌の近くに残り時間を出す。基本の5秒が残っている間は「5」から数え、切れたら持ち時間を「+20」のように数える。応答、サイコロ、局の結果は残り秒数だけを出す。
- 自動の人の名前の横に「自動」を出す。
- 残り秒数は、画面データに入っているサーバーの現在時刻との差から計算する。ブラウザの時計には頼らない。

### 破棄

- 条件：対局中のまま、最後の保存から10分たった。画面を開いている人がいれば時間切れが必ず申告されるので、これは「3人とも不在が10分」と同じ意味になる。3人とも自動で止まっている対局も含む。
- 処理：対局とルームを `abandoned` にする。結果と集計には残さない。牌譜（`game_events`）は残す。3人は新しいルームを作れる（`active_room_of` は `abandoned` を数えない）。
- タイミング：参加者がトップ画面、ルーム、対局の画面を開いたとき（その人の対局だけ）。加えて1日1回の定期実行（全部）。
- 破棄された対局やルームの画面を開いたら、「この対局は破棄されました」とトップへのリンクを出す。開いたままの画面から操作や申告を送って「対局が終わっている」が返ったら、画面を読み込み直す。

## 2. 作り

### 状態

`TableState`（`src/server/table.ts`）に `clock` を足す。DBの列は増やさない。

```ts
interface Clock {
  /** この状態を保存したサーバーの時刻（エポックms） */
  savedAt: number;
  /** いま待っている操作の期限（エポックms）。待っていなければ null */
  deadline: number | null;
  /** 残り持ち時間（ms） */
  bank: PerSeat<number>;
  /** 即ツモ切り中 */
  auto: PerSeat<boolean>;
}
```

`PlayerView` には `deadline`、`serverNow`（`clock.savedAt`）、`bank`（自分の分）、`auto`（3人分）を足す。

持ち時間の消費は期限から計算する。手番の操作を受けたとき、持ち時間を「期限までの残り」と比べて小さい方にする。基本の5秒（と最初の手番の+10秒）の間は、残りが持ち時間より長いので減らない。

`clock` は省略できる項目にする。`clock` のない状態（デプロイ時点で進行中の対局）は、次に誰かが操作したときに、持ち時間20秒、自動なしとして補い、そこから期限を付ける。画面データにも項目がないので、画面側で「期限なし、自動なし」として補う。終わった対局の画面データも同じ扱いにする。

### `clock.ts` の関数

- `startClock(table, now)`：対局の開始時。持ち時間を満たし、最初の期限（+10秒）を決める。
- `applyTimed(table, action, ctx)`：プレイヤーの操作。手番の操作なら持ち時間を減らし、操作した人の自動を解除し、`applyTableAction` を呼び、あとは `settle` に渡す。`resume` は自動を解除して `settle` に渡す（3人とも自動で止まっていた対局はここで再開する）。待ちの途中で復帰しても、その待ちの期限は変えない。止まっていた対局では期限を決め直す。
- `applyTimeout(table, ctx)`：時間切れの申告。期限前なら `IllegalActionError`。待たれている人に自動処理を当てて自動にし、`settle` に渡す。
- `settle`（内部）：自動の人が待たれている間、その人の自動処理を続けて当てる。3人とも自動なら止めて期限を `null` にする。止まったところで次の期限を決める。局が変わったら持ち時間を戻す。

`ctx` は `{ now: number; nextSeed: () => string; pickDice: (choices) => faces }`。

### APIの応答

| 場合                                 | 応答 |
| ------------------------------------ | ---- |
| 版番号が古い、対局が終わっている     | 409  |
| 期限前の申告、期限のない状態への申告 | 422  |
| 参加者でない                         | 404  |
| `/api/cron` の秘密の値が違う、未設定 | 401  |

時間切れの申告は参加者なら誰でも送れる。期限はサーバーの時計で確かめるので、早く進めることはできない。

### 画面からの申告

- 期限＋0.3秒＋席×0.2秒で `/tick` を送る。3人が同時に送るのを避けるため。
- 409 と 422 は画面データを取り直すだけで、エラーは出さない。通信に失敗したら2秒後にもう一度送る。
- 画面が裏に回っている間は送らない。表に戻ったときに期限を過ぎていれば送る。
- サーバーとの時計の差は、「受け取った時刻 − サーバーの時刻」の最小値で見積もる。サーバーの時刻には、画面データの `serverNow` と、対局のページを描いた時刻を使う（取り直した画面データは保存から時間がたっていて差が大きく出るため、最小値を使う）。

### 設定

- `CRON_SECRET`：Vercel の環境変数と GitHub の Secrets に同じ値を登録する。
- `APP_URL`：GitHub の Variables に本番のURLを登録する。
