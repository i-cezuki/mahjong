# フェーズ9：対局履歴と集計 設計

2026-10-02。`docs/SPEC.md` の Development Plan 9 にあたる。

## 目的

- 終わった対局の一覧（対局履歴）を、承認済みの全員が見られるようにする。
- プレイヤー別の通算成績を、全員分を並べて比べられるようにする。
- 順位やスコアだけでなく、局ごとの内容（和了、放銃、リーチの待ちの形、放銃時のシャンテン数など）まで集計する。

## やらないこと

- 日別の集計（ユーザーの判断で外した。`docs/SPEC.md` の「日別の集計」も消す）。
- 期間や相手での絞り込み、グラフ。
- 牌譜のリプレイ画面。牌譜の中身は今までどおり参加者だけが読める。
- 破棄された対局の集計。
- 金額換算。

## 1. 画面

| 画面                     | 内容                                                                                   |
| ------------------------ | -------------------------------------------------------------------------------------- |
| 対局履歴 `/history`      | 終わった対局を新しい順に並べる。日時、3人の名前、順位、持ち点、スコア、祝儀。全員分    |
| 成績 `/stats`            | 全員の通算成績を並べた表。主な項目（下の表の ★）だけを出す。名前から個人の成績へ進める |
| 個人の成績 `/stats/<id>` | その人の全項目を、分類ごとにまとめて出す                                               |

- ホームに「対局履歴」と「成績」へのリンクを足す。
- 対局履歴は新しい順に50件ずつ出し、「もっと見る」で続きを出す。
- 日時は日本時間で出す。
- 1局も集計のない人は、成績の表に出さない。
- 割る数が0の項目は「—」と出す。率は小数第1位までの％、平均は項目に合った桁で出す。
- 既存の画面（`Screen` の部品）と同じ見た目にする。卓の画面のような固定レイアウトにはしない。

## 2. 集計する項目

### 基本（半荘ごと。`game_results` から）

| 項目                  | 定義                           |
| --------------------- | ------------------------------ |
| ★ 対局数              | 終わった半荘の数               |
| ★ 平均順位            | 順位の平均                     |
| ★ 1位率、2位率、3位率 | それぞれの順位の回数 ÷ 対局数  |
| ★ 通算スコア          | スコア（支払い表の枚数）の合計 |
| ★ 通算祝儀            | 祝儀の枚数の合計               |
| 平均持ち点            | 最終持ち点の平均               |

### 局ごとの基本（牌譜から）

| 項目         | 定義                                                                    |
| ------------ | ----------------------------------------------------------------------- |
| 局数         | その人が参加した局の数                                                  |
| ★ 和了率     | 和了した局 ÷ 局数                                                       |
| ★ 放銃率     | 放銃した局 ÷ 局数                                                       |
| ★ リーチ率   | リーチした局 ÷ 局数                                                     |
| ★ 副露率     | ポンか大明槓を1回でもした局 ÷ 局数（暗槓と加槓だけの局は数えない）      |
| ツモ率       | ツモ和了の局 ÷ 和了した局                                               |
| 流局時聴牌率 | 流局で聴牌していた局 ÷ 流局した局                                       |
| ★ 平均和了点 | 和了で得た点（供託と本場を含む、その和了の受け取り）の合計 ÷ 和了した局 |
| ★ 平均放銃点 | 放銃で払った点の合計 ÷ 放銃した局                                       |
| 平均和了巡目 | 和了までに自分が切った牌の枚数の合計 ÷ 和了した局                       |

### リーチの詳細

| 項目             | 定義                                                                    |
| ---------------- | ----------------------------------------------------------------------- |
| ★ リーチ時良形率 | 良形のリーチ ÷ リーチした局                                             |
| リーチ時愚形率   | 愚形のリーチ ÷ リーチした局                                             |
| リーチ後和了率   | リーチして和了した局 ÷ リーチした局                                     |
| リーチ後放銃率   | リーチして放銃した局 ÷ リーチした局                                     |
| 一発率           | 一発が付いた和了 ÷ リーチして和了した局                                 |
| 裏ドラ率         | 裏ドラが1枚以上乗った和了 ÷ リーチして和了した局                        |
| 平均リーチ巡目   | リーチ宣言牌が自分の何枚目の打牌かの合計 ÷ リーチした局                 |
| 追いかけリーチ率 | 自分のリーチの時点で、ほかの誰かがすでにリーチしていた局 ÷ リーチした局 |
| 2倍リーチの回数  | 2倍リーチをした局の数                                                   |
| 2倍リーチ和了率  | 2倍リーチをして和了した局 ÷ 2倍リーチをした局                           |

リーチが成立しなかった（宣言牌でロンされた）局は、リーチした局に数えない。

### 放銃の詳細

| 項目                     | 定義                                                            |
| ------------------------ | --------------------------------------------------------------- |
| ★ 放銃時平均シャンテン数 | 放銃時のシャンテン数の合計 ÷ 放銃した局                         |
| 放銃時の内訳             | 聴牌（0）、1向聴、2向聴以上のそれぞれ ÷ 放銃した局              |
| リーチ者への放銃の割合   | 和了者（ダブロンならどちらか）がリーチしていた放銃 ÷ 放銃した局 |
| リーチ中の放銃の割合     | 自分がリーチ中だった放銃 ÷ 放銃した局                           |
| 副露中の放銃の割合       | 自分がポンか大明槓をしていた放銃 ÷ 放銃した局                   |

### このルール特有

| 項目             | 定義                                                                                   |
| ---------------- | -------------------------------------------------------------------------------------- |
| サイコロチャンス | 自分が出目を指定した回数、当たりの回数の合計、サイコロで動いた自分の祝儀の合計         |
| ポッチでの和了   | ポッチ、逆ポッチによる和了の回数                                                       |
| 役満             | 役満を和了した回数（流し役満と追加役満を含む。数え役満は含まない）                     |
| 飛ばした、飛んだ | 飛び賞を受け取った回数、飛んだ回数                                                     |
| 祝儀の内訳       | 和了で受け取った祝儀を、赤、金、裏、一発、役満に分けた枚数。別に飛び賞とサイコロの枚数 |

### 細かい決めごと

- **良形と愚形**：リーチ宣言牌を切ったあとの手牌の待ちで決める。待ち牌のうち1種類でも、和了形のどれかの読み方で順子の両面を埋める牌があれば良形（両面、3面張、両面とシャンポンの複合など）。それ以外は愚形（カンチャン、ペンチャン、単騎、ノベタン、シャンポン、七対子、国士）。場に見えている枚数は考えない。役の判定（平和）で使っている両面の判定と同じ基準にする。
- **放銃時のシャンテン数**：放銃した牌を切ったあとの自分の手牌（副露を含む）で数える。通常形、七対子、国士のうち一番小さい値。0が聴牌。七対子は、このルールに合わせて同じ牌4枚を2対子と数える。副露しているときは通常形だけ。抜いた花牌は手牌に含めない。
- **巡目**：その局で自分が切った牌の枚数。リーチ巡目は宣言牌を含む。和了巡目は、ツモなら和了の前に切った枚数＋1、ロンなら切った枚数＋1（次の自分の打牌の番で数える）。
- **ダブロン**：放銃は1回。放銃点は2人分の合計。「リーチ者への放銃」はどちらかがリーチしていれば数える。
- **ポッチ、逆ポッチ、流し役満**：和了として数える（和了率、平均和了点）。ツモ率の「ツモ」には入れない。逆ポッチで払う側は放銃に数えない。
- **放銃**：ロンされた局だけ。ツモられた局は数えない。
- **1局**：`roundStart` から `roundEnd`（とそのあとのサイコロ）まで。サドンデスの局も数える。

## 3. 作り

### 進め方

対局が終わったときに、牌譜から「その対局の1人分の集計値（回数と合計）」を計算して `game_stats` に保存する。成績の画面は、それを人ごとに足し合わせて率や平均を出す。

- 画面を開くたびに全牌譜を計算し直す案は、Vercel の無料枠（Active CPU）を使うので採らない。
- SQLだけで集計する案は、シャンテン数や待ちの形を計算できないので採らない。

牌譜（`game_events`）が元データなので、項目を足したくなったら版番号を上げて全対局を計算し直せる。

### 部品

| 場所                                 | 役割                                                                                                        |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| `src/engine/shanten.ts`（新規）      | シャンテン数。`shanten(concealed, melds): number`（−1 が和了形、0 が聴牌）                                  |
| `src/engine/waits.ts`（新規）        | 待ちの形。`isGoodWait(concealed, melds): boolean`。両面の判定は `yaku.ts` と同じ関数を使う                  |
| `src/stats/types.ts`（新規）         | 集計値の型 `GameStats`（すべて回数か合計の数値）と、版番号 `STATS_VERSION`                                  |
| `src/stats/analyze.ts`（新規）       | `analyzeGame(events): PerSeat<GameStats>`。純粋な関数。牌譜の配牌、ツモ、打牌、鳴きをたどって手牌を復元する |
| `src/stats/summary.ts`（新規）       | `addStats`（足し合わせ）と `summarize`（率と平均。0で割らない）。純粋な関数                                 |
| マイグレーション                     | `game_stats` の表、RLS、`save_game_stats` 関数、`game_results` のポリシーの変更                             |
| `src/server/stats.ts`（新規）        | 終局時の計算と保存、未計算の対局の計算、画面用の読み出し                                                    |
| `src/server/games.ts`、`/api/cron`   | 終局時と定期実行から `stats.ts` を呼ぶ                                                                      |
| `src/app/history/`、`src/app/stats/` | 画面                                                                                                        |

`src/stats/` はエンジンにだけ依存する。UI、DB、通信には依存しない。

### 表 `game_stats`

| 列          | 内容                                |
| ----------- | ----------------------------------- |
| `game_id`   | 対局                                |
| `player_id` | プレイヤー                          |
| `version`   | 計算方法の版番号（`STATS_VERSION`） |
| `stats`     | 集計値（JSON。`GameStats`）         |

主キーは `(game_id, player_id)`。読めるのは承認済みの全員。書けるのはサーバーだけ（`save_game_stats(p_game, p_version, p_stats)` で3人分をまとめて置き換える）。

成績の画面は、`game_stats` と `game_results` を全行読んでサーバーで足し合わせる。身内の規模（数十人、数百〜数千半荘）ならこれで足りる。

### 計算のタイミング

1. **終局時**：最後の操作を保存したあと、その対局の牌譜を読んで計算し、保存する。失敗しても操作の応答は成功のままにする（対局の結果には影響させない）。
2. **1日1回の定期実行（`/api/cron`）**：終わった対局のうち、`game_stats` がないもの、版番号が古いものを計算する。1回の実行で最大50対局。応答に計算した数を足す。

リリース直後は、定期実行を手動で動かして既存の対局を計算する。

### 権限

- `game_results`：「参加した対局」から「承認済みなら全員分」に広げる。
- `game_stats`：承認済みなら全員分を読める。
- `game_events`、`games`：変えない。対局履歴は `game_results` と `profiles` から作る（日時は `game_results.created_at`）。

### エラーの扱い

- 牌譜が壊れている、想定外のイベントがあるなど、分析で例外が出た対局は飛ばして、ほかの対局の計算を続ける。定期実行の応答に失敗した数を入れる。
- 集計値のない対局があっても、成績の画面は基本の項目（`game_results` から）を出す。

## 4. テスト

- **シャンテン数**：既知の手牌（和了形、聴牌、1向聴、七対子、国士、副露あり、4枚使いの七対子）。乱数で作った多数の手牌で、「−1 ⇔ `isCompleteHand`」「0 ⇔ 和了形でなく、4枚使い切りを除いた待ち牌がある」が既存の判定と一致すること。
- **待ちの形**：両面、3面張、カンチャン、ペンチャン、単騎、ノベタン、シャンポン、両面とシャンポンの複合、七対子。
- **牌譜の分析**：牌の並びを決めた局で、リーチ（良形、愚形、追いかけ、不成立）、放銃（シャンテン数、リーチ中、副露中）、一発、裏ドラ、ダブロン、ポッチ、サイコロ、飛び、祝儀の内訳。自動対局した半荘で、局数が3人で同じこと、和了点と放銃点とツモられた点の合計が点棒の移動と合うこと、和了で受け取った祝儀の内訳の合計が牌譜の祝儀の移動と合うこと。
- **集計**：足し合わせと、0で割らないこと。
- **DB（pgTAP）**：`game_stats` と `game_results` を承認済みの他人が読めること、未承認は読めないこと、クライアントから書けないこと。
- **画面**：ローカルで半荘を数回自動対局させ、ブラウザで3画面を確かめる。
