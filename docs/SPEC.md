# Requirements

## 目的と規模

- 身内だけで遊ぶオンライン3人麻雀。利用者は数人〜数十人。
- 友人にURLを送り、ブラウザだけで3人がリアルタイムに対局できる。
- 月額0円を目標とする（Vercel無料枠、Supabase無料枠、GitHub）。有料サービスは勝手に採用しない。
- CPU対戦と観戦は作らない。エンジンは将来CPUを足せる構造にする。

## 最初のリリースに含めるもの（確定）

- Googleログイン、管理者承認、表示名
- ルーム作成、ルームコードでの参加、3人そろったら自動開始、再戦
- 東南戦の完全な対局（配牌、ツモ、打牌、ポン、槓、リーチ、和了、流局、役、点数、祝儀、サイコロチャンス）
- 持ち時間、時間切れの自動処理、切断と再接続
- 対局履歴、プレイヤー別の通算の集計（日別の集計は作らない）
- 牌譜（全イベント）の保存。リプレイ画面は後回し

## 含めないもの（確定）

- CPU、観戦、対局中の退出ボタン、対局の打ち切り、ルームごとのルール変更、金額換算のレート

# Mahjong Rules

## 牌（確定）

総数112枚。

| 種類 | 枚数 | 備考                                  |
| ---- | ---- | ------------------------------------- |
| 萬子 | 8    | 1萬と9萬のみ（2〜8は抜く）            |
| 筒子 | 36   | 5筒は赤1枚、金1枚、通常2枚            |
| 索子 | 36   | 5索は赤1枚、金1枚、通常2枚            |
| 字牌 | 28   | 白4枚のうち1枚がポッチ、1枚が逆ポッチ |
| 花牌 | 4    | 抜きドラ                              |

- 赤と金はどちらもドラ1翻。鳴いても有効。
- 北は抜かない。役のつかない客風。
- 表示牌が1萬ならドラは9萬、9萬なら1萬。字牌は東→南→西→北→東、白→發→中→白。
- ドラ表示牌が花牌のときは花牌がドラになる（抜いた花牌1枚が抜きドラ1翻＋ドラ1翻）。裏ドラ表示牌と槓ドラ表示牌が花牌の場合も同じ。

## 花牌（確定）

- 抜くと1枚につき1翻。強制抜きで、サーバーが自動で抜いて嶺上牌から補充する。
- 配牌に入っていた花牌は、自分の手番が来た時点で抜く。
- 抜いても鳴き扱いにならず、一発、ダブルリーチ、天和、地和の権利は消えない。
- 補充牌での和了に嶺上開花は付かない（嶺上開花は槓のときだけ）。
- 花牌に祝儀は付かない。
- 派生する仕様：花牌を抱えている間は手が完成しないので、最初の手番より前のロンはできない。

## 牌山（確定）

- 嶺上牌は8枚固定（花牌4枚＋槓4回でちょうど使い切る）。
- ドラ表示牌の1山（上が表示牌、下が裏ドラ）を残す。
- 配牌は13枚×3人の39枚。残り63枚（親の第一ツモを含む）をツモり切る。
- 槓ドラ、裏ドラ、槓裏あり。槓1回ごとに隣の1山が槓ドラ表示と槓裏になり、ツモれる牌が2枚減る。
- 槓ドラは暗槓、明槓、加槓すべて即めくり。
- 派生する仕様：槓は1局に合計4回まで（嶺上牌が尽きるため）。

## 対局の進行（確定）

- 東南戦固定。延長なし。
- 30000点持ち。
- 連荘は親の和了と、親テンパイの流局。流局は必ず本場＋1。
- ノーテン罰符：1人テンパイは2人から1000ずつ受け取る。2人テンパイはノーテンの1人が1000ずつ払う。
- 途中流局はなし（九種九牌、四槓流れともになし）。
- 飛び：局の精算が終わった時点で持ち点が0以下の人がいれば終了。0点ちょうども飛び。
- オーラスの終了条件：
  - 子が和了する、または流局で親がノーテンなら終了。
  - 親が和了する、または流局で親がテンパイなら、親が単独1位のときだけ終了。そうでなければ連荘。
- 和了やめ、聴牌やめの選択はなし。
- 終了時に残った供託はトップが取る。
- 同点は起家に近い方が上位。
- 3人とも30000点で終わった場合は、サドンデスでもう1局行う。

## 2倍リーチ（確定）

- 通常のリーチの代わりに、供託5000点で宣言できる。持ち点5000点未満でも可。
- 1人につき半荘に1回まで。成立した（宣言牌でロンされなかった）時点で使ったことになる。宣言牌でロンされて成立しなかった場合は、まだ使える。使ったあとは通常のリーチだけ宣言できる。
- 自分が和了したときに受け取る祝儀が2倍になる。飛び賞だけは2倍にならない。
- 自分が放銃したときに払う祝儀は2倍にならない。
- 供託の5000点は通常のリーチ棒と同じく和了者が取る。

## オープンリーチ（確定）

- 通常のリーチの代わりに、供託2000点で宣言できる。持ち点2000点未満でも可。回数の制限はない。
- 2倍リーチとは同時に宣言できない。リーチは通常、2倍、オープンから1つを選ぶ。
- 役はリーチ（ダブルリーチ）に1翻を足す。リーチなら2翻、ダブルリーチなら3翻。
- 宣言牌が通ってリーチが成立した時点から、手牌を全員に公開する。手番のツモ牌は切るまで見せない。宣言牌でロンされたら不成立で、供託も払わず、手牌も公開しない（応答待ちを隠すため、応答できない人には応答待ちの間も公開している）。
- オープンリーチに放銃しても、支払いは通常どおり（役満払いなどはない）。
- 追加役満の「リーチのみ」は、オープンリーチでは成立しない（オープンリーチの1翻が付くため）。
- 一発、裏ドラ、フリテン、リーチ後の暗槓、ポッチ、祝儀は通常のリーチと同じ。
- 成績ではリーチとして数える。

## ポッチと逆ポッチ（確定）

- リーチしていない人には普通の白。切れる、ポンできる、面子に使える。
- 他家が切ったポッチは普通の白で、ロンでは効果がない。
- 河や副露に出たポッチと逆ポッチは全員が識別できる。
- リーチ後に引いたら強制で和了扱いになる。花牌や槓の補充牌で引いても有効。
- 高め取り：待ち牌のうち、裏ドラ込みで最も高くなる牌で和了したことにする。サーバーが自動計算する。
- **ポッチ**：ツモ和了として扱う。門前清自摸、一発、海底が付く。
- **逆ポッチ**：和了扱いだが支払いが逆になる。高め取りした手をツモったときに相手が払うはずだった点数と祝儀を、引いた本人が2人それぞれに払う。本場分も払う。リーチ棒と供託は本人が回収する。親なら連荘。
- 逆ポッチの支払いで本人が飛んだ場合、飛び賞はトップが受け取る。
- 2倍リーチ中は、ポッチも逆ポッチも祝儀が2倍。

## 役（確定）

- 標準の役。三色同順は萬子がないので成立しない。
- 七対子は、同じ牌4枚を2対子として数える（4枚使いの七対子あり）。清一色七対子でも同じ。
- 追加役満：
  - **萬子の混一色**：1萬と9萬＋字牌。鳴いても役満。
  - **清一色七対子**：筒子または索子のみの七対子。
  - **リーチのみ**：リーチ以外の役がなく、表ドラ、裏ドラ、赤、金、花牌がすべて0。ロン和了のみ。一発やダブルリーチが付いたら不成立。
  - **流し役満**：流局時に自分の捨て牌がすべて么九牌で、1枚も鳴かれていない。和了扱いで、支払いは役満ツモと同じ。供託と本場も取る。ノーテン罰符はなし。2人同時に成立したら両方成立。
- ダブル役満は役満同士の複合のみ（四暗刻単騎などの単独ダブルはなし）。点数、役満祝儀、サイコロチャンスの回数がすべて2倍になる。
- 数え役満は13翻以上。点数は役満と同じ。

# 点数と精算

## 点数表（確定）

符計算なし。点数は1000点単位。

| 翻               | 子ロン | 子ツモ（子払い/親払い） | 親ロン | 親ツモ      |
| ---------------- | ------ | ----------------------- | ------ | ----------- |
| 1                | 1000   | 1000 / 1000             | 2000   | 1000オール  |
| 2                | 2000   | 1000 / 1000             | 4000   | 2000オール  |
| 3                | 4000   | 1000 / 3000             | 6000   | 3000オール  |
| 4〜5（満貫）     | 8000   | 3000 / 5000             | 12000  | 6000オール  |
| 6〜7（跳満）     | 12000  | 4000 / 8000             | 18000  | 9000オール  |
| 8〜10（倍満）    | 16000  | 6000 / 10000            | 24000  | 12000オール |
| 11〜12（三倍満） | 24000  | 8000 / 16000            | 36000  | 18000オール |
| 役満、数え役満   | 32000  | 12000 / 20000           | 48000  | 24000オール |

- 本場：ロンは放銃者が1本につき＋1000。ツモは2人がそれぞれ1本につき＋1000。

## 支払い表（確定）

終局時の持ち点と順位で枚数を決める。1着は2着と3着の収支合計の符号を反転した枚数を受け取る。

| 終了時の持ち点 | 2着 | 3着（2着も30000未満） | 3着（2着が30000以上） |
| -------------- | --- | --------------------- | --------------------- |
| 40000〜        | ＋8 |                       |                       |
| 35000〜39000   | ＋5 |                       |                       |
| 30000〜34000   | ＋2 |                       |                       |
| 25000〜29000   | −11 | −21                   | −26                   |
| 20000〜24000   | −13 | −23                   | −28                   |
| 15000〜19000   | −15 | −25                   | −30                   |
| 10000〜14000   | −18 | −28                   | −33                   |
| 5000〜9000     | −20 | −30                   | −35                   |
| 0〜4000        | −23 | −33                   | −38                   |

- マイナスの持ち点は「0〜4000」の行を使う。
- 1000点未満の端数が出た場合は切り上げて行を決める。

## 祝儀（確定）

スコア（支払い表の枚数）とは別に記録する。

| 対象   | 枚数                       |
| ------ | -------------------------- |
| 赤     | 1枚                        |
| 金     | 2枚                        |
| 一発   | 1枚                        |
| 裏ドラ | 乗った枚数分               |
| 役満   | ロンは20枚、ツモは10枚ずつ |
| 飛び賞 | 2枚（飛んだ本人が払う）    |

- 鳴いた手でも赤と金の祝儀は付く。
- ロンは放銃者が払う。ツモは2人がそれぞれ同じ枚数を払う。
- 役満祝儀は追加役満と流し役満にも付く。数え役満には付かない。
- 役満を和了したときも、赤、金、一発、裏の祝儀を加算する。
- 飛び賞の受取人：ロンやツモで直接飛ばしたときは和了者。流局や横移動で飛んだときはその時点のトップ。ツモで2人同時に飛ばしたら2枚ずつ。

## サイコロチャンス（確定）

- 発動条件：
  - 花牌を4枚すべて抜いて和了した
  - 役満を和了した（追加役満と流し役満を含む。数え役満は含まない）
  - ポッチまたは逆ポッチを一発でツモった
- 内容：ゾロ目以外の出目を1組指定し（順不同）、2個のサイコロを4回振る。当たるたびに70枚。ゾロ目は回数を消費しない。
- 支払い：ツモなら2人がそれぞれ払う。ロンなら放銃者が払う。逆ポッチは引いた本人が2人に払う。
- 出目を指定するのは和了者。逆ポッチの場合は引いた本人。
- 2倍リーチ中は当たり1回が140枚。
- 条件が重なったら、その数だけチャンスがある。
- サイコロはサーバー側の乱数で振り、出目を牌譜に記録する。

# Architecture

## 構成（確定：Vercelのルートハンドラ＋Postgres）

```text
ブラウザ（Next.js / React）
   │  操作の送信（HTTPS）          ▲ 自分用の画面データの更新通知
   ▼                               │
Vercel ルートハンドラ（Node）       Supabase Realtime
   │  エンジン（純粋なTypeScript）   ▲
   ▼                               │
Supabase Postgres ─────────────────┘
```

- **エンジン**：UI、DB、通信に依存しない純粋なTypeScript。入力は「現在の状態＋操作」、出力は「新しい状態＋イベント」。
- **サーバー**：操作ごとに、状態の読込、検証、適用、保存を行う。クライアントが送るのは「何をしたいか」だけで、結果はサーバーが決める。
- **Realtime**：通知専用。ゲームロジックは持たない。

## ディレクトリ（提案）

```text
src/
  engine/      牌、牌山、手牌、和了判定、役、点数、祝儀、状態機械
  server/      DBアクセス、認証確認、操作の受付、画面データの生成
  stats/       牌譜の分析、集計値の足し合わせ、画面に出す項目
  app/         画面とAPIルート
  components/  卓、牌、ボタン
supabase/
  migrations/  スキーマとRLS
```

## 同時操作の扱い（提案）

- 対局ごとに版番号を持つ。保存は「読み込んだ版番号と一致するときだけ更新する」Postgres関数1回で行い、状態、イベント、3人分の画面データを同時に書く。
- 版番号が合わなければ保存は失敗し、操作は拒否される。二重送信や同時操作で状態が二重に進むことはない。

## 持ち時間の実現（提案）

- サーバーレスには常駐タイマーがないので、期限の時刻を対局の状態（`clock`）に記録し、画面データに入れて3人に送る。
- 期限を過ぎたら、画面を開いている誰かのクライアントが時間切れを申告する（`POST /api/games/:id/tick`）。サーバーは自分の時計で期限を検証してから自動処理する。期限を過ぎていても、申告が処理される前に届いた本人の操作は受け付ける。
- 切断は検知しない。いなくなった人は最初の1回だけ期限いっぱい待たれ、時間切れで即ツモ切りになる。
- 3人とも不在だと対局は進まない。最後の保存から10分たった対局は破棄する（`abandon_stale_games`）。破棄は、参加者がトップ画面、ルーム、対局の画面を開いたときと、1日1回の定期実行で行う。破棄した対局は結果と集計に残さない。
- 時間のルールは `src/server/clock.ts` にある。エンジンは時刻を知らない。

## 無料枠の制約

- Supabase無料枠は1週間アクセスがないと一時停止する。GitHub Actions（`.github/workflows/cron.yml`）が1日1回 `POST /api/cron` を呼んで防ぐ（確定）。同じ定期実行で放置対局の破棄も行う。`CRON_SECRET` を Vercel の環境変数と GitHub の Secrets に、本番のURLを GitHub の Variables の `APP_URL` に登録する。リポジトリに60日間動きがないと GitHub が定期実行を止めるので、止まったら Actions の画面から有効に戻す。
- Realtimeの同時接続数と月間メッセージ数、Vercelの関数実行回数には上限がある。2026-10-02に公式ページで確認した数値は次のとおり。フェーズ6のデプロイで実測する。
  - Supabase Free：DB 500MB、Realtime 同時200接続、Realtime 月200万メッセージ、転送量5GB、1週間アクセスがないと一時停止、有効なプロジェクトは2つまで。
  - Vercel Hobby：関数の実行 月100万回、Active CPU 月4時間、転送量100GB、非商用の個人利用に限る。上限を超えると30日間その機能が止まる。
  - 目安：1半荘は操作が約1000回、画面データの通知が約3000メッセージ。最初に当たるのは Vercel の Active CPU（1回30msとして月480半荘ほど）で、次が Realtime のメッセージ数（月660半荘ほど）。身内の利用なら収まる。

# Game State

## ルーム

```text
WAITING（3人待ち） → IN_GAME → FINISHED →（3人が再戦を押す）→ IN_GAME
                        └→ ABANDONED（3人とも不在が10分）
```

## 対局内の状態（提案）

```text
ROUND_START        配牌
   ↓
TURN_START         ツモ、花牌の自動抜きと補充、ポッチ判定
   ↓
AWAIT_TURN_ACTION  打牌 / リーチして打牌 / ツモ和了 / 暗槓 / 加槓
   ├─ 槓 → 嶺上ツモ、槓ドラ → AWAIT_TURN_ACTION
   ├─ ツモ和了、ポッチ、逆ポッチ → ROUND_SETTLE
   └─ 打牌
        ↓
AWAIT_RESPONSES    他家のロン / ポン / 大明槓 / スルー（権利者がいるときだけ）
   ├─ ロン（2人ならダブロン）→ ROUND_SETTLE
   ├─ ポン → 鳴いた人の AWAIT_TURN_ACTION
   ├─ 大明槓 → 嶺上ツモ → 鳴いた人の AWAIT_TURN_ACTION
   └─ 全員スルー → 次の人の TURN_START（山がなければ流局で ROUND_SETTLE）
        ↓
ROUND_SETTLE       点数と祝儀の計算、流し役満の判定
   ↓
DICE_CHANCE        発動したときだけ。出目の指定を待って振る
   ↓
ROUND_RESULT       全員の確認か15秒で次へ
   ↓
次の ROUND_START または GAME_END（終局の精算）
```

- 搶槓と国士の暗槓ロンがないので、暗槓と加槓に応答待ちはない。
- ロンはポンと槓より優先する。
- 応答待ちになったことは、応答できる人（まだ応答していない人）にしか見せない。ほかの人の画面では、打牌が通ったあとと同じに見せる（手番は次の人へ移り、打牌は強調せず、リーチの宣言牌なら供託を払い、オープンリーチの手牌も公開する）。待っている時間は、打牌が通ったあと次の人のツモを見せるまでに毎回ランダムな間（0.4〜1.6秒）を入れてまぎれさせる。この間は次の人の期限に足すので、持ち時間は減らない。ポンや槓のあとには入れない。

## 持ち時間（確定）

| 場面                 | 時間                                        |
| -------------------- | ------------------------------------------- |
| 自分の手番           | 基本5秒＋局ごとの持ち時間20秒（毎局回復）   |
| 他家の打牌への応答   | 基本5秒＋局ごとの持ち時間20秒（手番と共有） |
| 局の結果表示         | 全員の確認か15秒                            |
| サイコロの出目の指定 | 20秒で自動指定                              |

- 時間切れは自動ツモ切り。応答は自動でスルー。
- 一度時間切れした人や切断中の人の以降の手番は、持ち時間を待たずに即ツモ切りにする。応答は即スルーにする。再接続すれば復帰できる。

# 対局履歴と集計

フェーズ9で決めた内容。項目と定義はユーザーが確認した。

## 画面

| 画面                     | 内容                                                                                |
| ------------------------ | ----------------------------------------------------------------------------------- |
| 対局履歴 `/history`      | 終わった対局を新しい順に50件ずつ。日時（日本時間）、3人の順位、持ち点、スコア、祝儀 |
| 成績 `/stats`            | 全員の通算成績を並べた表。主な項目だけ                                              |
| 個人の成績 `/stats/<id>` | その人の全項目                                                                      |

破棄された対局は入れない。割る数が0の項目は「—」。

## 作り

- 対局が終わると、牌譜（`game_events`）から3人それぞれの集計値（回数と合計）を計算して `game_stats` に保存する。計算は応答を返したあとに行う。
- 成績の画面は、`game_results` と `game_stats` を人ごとに足し合わせて、率と平均を出す。
- 1日1回の定期実行が、集計値のない対局と、古い版番号（`STATS_VERSION`）で計算した対局を計算する（1回に最大50対局）。項目や数え方を変えたら版番号を上げる。
- 計算は `src/stats/` の純粋な関数で行う。シャンテン数と待ちの形はエンジン（`src/engine/shanten.ts`、`waits.ts`）にある。画面に出す項目の一覧は `src/stats/metrics.ts`。

## 定義

| 項目                                                             | 定義                                                                                                                            |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 和了率、放銃率、リーチ率、副露率                                 | それぞれの局 ÷ 参加した局数。副露は、ポンか大明槓を1回でもした局（暗槓と加槓だけの局は数えない）                                |
| ツモ率、平均和了点、平均和了巡目                                 | 和了した局で割る。和了点は供託と本場を含む                                                                                      |
| 流局時聴牌率                                                     | 流局で聴牌していた局 ÷ 流局した局                                                                                               |
| 平均放銃点                                                       | 放銃で払った点 ÷ 放銃した局。ダブロンは放銃1回で、2人分の合計                                                                   |
| 放銃                                                             | ロンされた局だけ。ツモられた局、逆ポッチで払った局は数えない                                                                    |
| リーチ                                                           | 成立したリーチだけ。宣言牌でロンされたリーチは数えない                                                                          |
| 良形                                                             | リーチ宣言牌を切ったあとの待ち牌のうち1種類でも、和了形のどれかの読み方で順子の両面を埋める（平和と同じ判定）                   |
| 愚形                                                             | それ以外（カンチャン、ペンチャン、単騎、ノベタン、シャンポン、七対子、国士無双）                                                |
| リーチ後和了率、リーチ後放銃率、追いかけリーチ率、平均リーチ巡目 | リーチした局で割る。追いかけは、自分のリーチの時点でほかの誰かがリーチ済み                                                      |
| 一発率、裏ドラ率                                                 | リーチして和了した局で割る                                                                                                      |
| 放銃時のシャンテン数                                             | 放銃した牌を切ったあとの手牌で数える。通常形、七対子（同じ牌4枚は2対子）、国士無双の最小。0が聴牌。副露しているときは通常形だけ |
| 巡目                                                             | その局で自分が切った牌の枚数。リーチ巡目は宣言牌を含む。和了巡目は切った枚数＋1                                                 |
| ポッチ、逆ポッチ、流し役満                                       | 和了として数える。ツモ率の「ツモ」には入れない                                                                                  |
| 役満                                                             | 役満を和了した回数。流し役満と追加役満を含み、数え役満は含まない                                                                |
| 祝儀の内訳                                                       | 和了で受け取った祝儀を、赤、金、裏ドラ、一発、役満に分けた枚数。飛び賞とサイコロは別に数える                                    |
| サイコロチャンス                                                 | 自分が出目を指定した回数、当たりの回数、サイコロで動いた自分の祝儀（払った分は負）                                              |

# Database Schema

提案。クライアントからの書き込みは一切許可せず、すべてAPIルート経由にする。

| テーブル       | 内容                                             | クライアントから読める範囲         |
| -------------- | ------------------------------------------------ | ---------------------------------- |
| `profiles`     | 表示名（重複不可）、承認状態、管理者フラグ       | 承認済みユーザーは全員分の表示名   |
| `rooms`        | ルームコード、状態                               | 自分が参加しているルーム           |
| `room_members` | ルームと参加者                                   | 自分が参加しているルーム           |
| `games`        | 対局の公開情報（席順、状態、版番号）             | 自分が参加している対局             |

# Realtime Protocol

提案。フェーズ6で実装した内容に合わせてある。

- 各クライアントは `game_views` の自分の行の変更だけを購読する。RLSにより他人の行は届かない。
- ルームの画面は `rooms` の自分のルームの変更を購読する。メンバーの増減、対局の開始、再戦の表明のたびにサーバーが `updated_at` を更新する。
- 操作は `POST /api/games/:id/actions` に送る。内容は操作の種類、対象の牌、自分が見ていた版番号。席は送らない（ログイン中のユーザーからサーバーが決める）。
- 打牌、リーチ、スキップ、局の結果の確認は、応答を待たずに自分の画面へ先に出す（確定）。結果が自分の手元だけで決まる操作に限る。応答が返るまで次の操作はできない。サーバーに拒否されたら元の画面に戻す。ツモ、ロン、鳴き、サイコロは応答を待つ。
- サーバーは版番号の一致、手番、牌の所持、合法性を検証してから適用する。結果は `game_views` の更新として3人に届く。操作した本人には、応答でも新しい画面データを返す。
- 画面データには、サーバーが計算した「いま可能な操作の一覧」、3人のうち最も早い期限（申告用）、自分の期限、待ちが始まった時刻、保存したサーバーの時刻、自分の持ち時間、即ツモ切り中の人を含める。クライアントは合法手を自分で判定しない。残り時間は、保存したサーバーの時刻との差から計算する。
- 局の結果は3人が「確認」を送るか、15秒たつと次の局へ進む。
- 再接続やブラウザ更新のときは、自分の画面データを取得し直せば復帰できる。取り直しはブラウザからSupabaseを直接読む（RLSで自分の行だけ）ので、Vercelの関数は使わない。
- 通知はまれに届かないことがあるので、対局中は4秒ごとに自分の画面データの版番号だけを読み、進んでいたら取り直す。
- 時間切れの申告は `POST /api/games/:id/tick`。期限＋0.3秒＋席×0.2秒で送り、画面データが進むまで2秒ごとに送り直す。即ツモ切りの解除は、操作と同じ `POST /api/games/:id/actions` に `resume` を送る。

| API                           | 内容                                                                   |
| ----------------------------- | ---------------------------------------------------------------------- |
| `POST /api/rooms`             | ルームを作る                                                           |
| `POST /api/rooms/join`        | ルームコードで参加する。3人目で対局が始まる                            |
| `POST /api/rooms/:id/leave`   | 3人待ちのルームから抜ける                                              |
| `POST /api/rooms/:id/rematch` | 再戦を押す。3人そろうと次の対局が始まる                                |
| `POST /api/games/:id/actions` | 対局の操作                                                             |
| `GET /api/games/:id/view`     | 自分の画面データ（スクリプトからの確認用）                             |
| `POST /api/games/:id/tick`    | 時間切れの申告。本文は版番号だけ                                       |
| `POST /api/cron`              | 定期実行。放置対局を破棄し、集計値のない対局を計算する（秘密の値つき） |

応答のエラーは、401 未ログイン、403 未承認、404 参加者でない、409 版番号が古い・対局が終わっている・ほかのルームに参加中、422 いまはできない操作（期限前の時間切れの申告を含む）、400 形のおかしい要求。

# Security

- **秘匿情報**：他家の手牌、山、次のツモ、裏ドラ、乱数の種は `game_secrets` にだけ置き、クライアントには送らない。画面データは1つの関数で生成し、非公開の牌が混ざらないことをテストで検証する。
- **認証**：Googleログインのみ。初回は承認待ちになり、管理者（1人、メールアドレスで固定）が承認する。未承認のユーザーはAPIもRLSも通らない。
- **アクセス制御**：ルームと対局は参加者だけが読める。牌譜は対局終了後に参加者だけが読める。終わった対局の結果と集計値は、承認済みなら全員分を読める（身内で成績を比べるため）。
- **不正な要求**：すべての操作をサーバーで検証する。版番号の不一致は拒否するので、二重打牌、再送、古い要求の送り直しは無効になる。
- **複数接続**：同じアカウントで後から開いた画面を有効にし、古い画面には「別の画面で開かれました」と表示する。同時に参加できる対局は1つだけ。
- **乱数**：局ごとにサーバーで暗号学的乱数から種を作る。種は対局終了まで公開しない。終了後は牌譜の一部として参加者に公開する。
- **受け入れる制約**：
  - 管理者はDBを直接見られるので、技術的には対局中の全情報を見られる。
  - 打牌のあとに応答待ちが発生すると「誰かが鳴けるかロンできる」ことが伝わる。オンライン麻雀に共通の性質として受け入れる。

# UI

確定した内容。

- スマホは横画面に固定する（確定）。縦に持ったときも卓を90度回して、横画面のまま出す。PCでも同じ配置。
- 配色は暗い背景に明るい枠線。牌は立体感のない平面のカード状。牌山は、卓の上の中央に残り枚数の数字と、上下2段に並べた小さな牌で出す（左から嶺上牌、表向きのドラ表示牌、ツモ山。次にツモる牌は水色）。
- 配置：
  - 中央のパネルに、局、本場と供託、ドラ（表示牌の次の牌。表示牌そのものは山に表向きで出す）、3人の持ち点と風
  - 河は中央パネルの周りに3方向（自分が下、下家が右、上家が左）。相手の河は、捨てた人から見た向きに牌を回して置く（上家は牌の上が右、下家は牌の上が左）。1列目が中央パネルの隣
  - 相手の手牌は左右に裏向きで枚数だけ。抜いた花牌と副露はその近くに表向き
  - 自分の手牌は下
- 手牌は自動で並べ替える。ツモった牌は並べ替えに混ぜず、手牌の右端に少し離して置く。
- 打牌は2回タップ（1回目で牌が浮き、同じ牌をもう一度タップで打牌）。
- 中央のパネルをタップすると、2秒の間、相手2人の持ち点を自分との点差（相手−自分。相手が上ならプラス）に変えて出す。自分の持ち点はそのまま出す。
- 手牌とボタン以外の同じ場所を素早く2回タップ（0.35秒以内）すると、ツモ牌をそのまま切る（ツモ切り）。離れた場所の2回（端末を持ち直したときなど）は数えない。
- ポン、槓、ロン、ツモ、リーチ、スキップはボタンで選ぶ。リーチは通常、2倍、オープンから選ぶ。
- 自動和了と鳴きなしの切り替えボタンを付ける。
- 花牌を引いたときは、自分の画面ではいったんツモ牌の位置に花牌を出し、約0.5秒後に花に移して補充牌を出す（サーバーは抜いて補充するところまで一度に済ませ、画面が順に見せる）。続けて引いたら1枚ずつ見せる。見せている間は操作できない。
- リーチ後は、和了牌以外を自動でツモ切りする（引いた牌が見えるよう少し待ってから切る）。和了牌を引いたときと、暗槓ができるときは止まって本人が選ぶ。
- 卓は 1040×480 の固定の配置を、画面に収まるように全体で拡大縮小する（スマホの横画面に合わせた横長の比率）。
- サイコロチャンスは、出目を指定すると3人の画面で1回ずつ順番に転がして見せる。結果はサーバーが先にまとめて決める。再生が終わるまで、確認ボタンと祝儀の累計は出さない。
- リーチ、2倍リーチ、オープンリーチ、ポン、カン、ロン、ツモ、ポッチは、宣言した人の席の側（自分は下、上家は左、下家は右）から、名前と発声をカットインで大きく出す（確定）。リーチと鳴きは約1.4秒。和了は約0.5秒出して、その間は局の結果を出さずに待つ。画面を開いた時点ですでに起きていたものは出さない。流し役満は出さない。
- 相手が手牌から切った（手出しした）ときは、その人の河の下に「手出し」の吹き出しを約1秒出す（確定）。ツモ切りと自分の打牌では出さない。河の牌に印は付けない。
- 副露の鳴いた牌は横向きにして、鳴いた相手の側に置く（確定）。鳴いた人から見て上家（左の人）からなら左端、下家（右の人）からなら右端。加槓で加えた牌は、鳴いた牌の隣に横向きで並べる。相手の副露も同じ決まりで並べる。
- 局の結果は卓の上に重ねて出す。「卓を見る」で一時的に閉じられる。
- 牌の絵柄は麻雀王国の麻雀素材（<https://mj-king.net/sozai/> の牌画2）を使う。素材に無い牌（赤5、金5、ポッチ、逆ポッチ、花牌）は素材を加工して作る。裏向きは青い無地。参考画像からは配置と雰囲気だけを借りる。
- バグ報告ボタンと操作ログの文字表示は付けない。

画面の一覧（提案）：ログイン、承認待ち、ホーム、ルーム待機、対局、局の結果、サイコロチャンス、終局の結果、対局履歴、集計、管理（承認）。

# Testing

- **エンジンの単体テスト**：牌山の生成、配牌、花牌抜き、ツモ、打牌、ポン、槓、リーチ、2倍リーチ、フリテン、ポッチ、逆ポッチ、流局、連荘、親流れ、オーラスの終了条件、飛び。

- **役のテスト**：標準の役と追加役満を、成立する手と成立しない手の両方で確認する。
- **自動対局による検証**：乱数で合法手を選ぶ対局を大量に回し、次が常に成り立つことを確認する。
  - 牌の総数が112枚のまま
  - 3人の持ち点と供託の合計が90000点のまま
  - スコアの枚数と祝儀の枚数の合計がそれぞれ0
  - 画面データに非公開の牌が含まれない
- **RLSのテスト**：他人の画面データ、`game_secrets`、進行中の牌譜が読めないこと。
- **通しのテスト**：3つのブラウザで1半荘を最後まで進める。
- TypeScript strict、ESLint、Prettierを使う。
